## 2. 第一版范围与约束

- 第一版核心范围：仓库选择与记忆、引用选择、日期过滤、摘要与改动预览、完整代码导出、固定目录更新、保留项设置、失败恢复、手动fetch及依赖声明变化提示。
- 输出的Git代码部分是所选提交的**全部普通受跟踪文件的Git blob内容**，包含二进制；另加用户显式选中的可保留本地路径。没有`.git`；源仓库的未提交文件不会随导出带入。精确定义见P-03/P-07。
- 未选保留的本地修改、新增文件、依赖和环境文件随旧内容移除。界面显示本次目标路径和保留清单，按钮附近说明“更新代码，移除未保留的旧内容”；首次绑定只接受空专用目录是P-09的方案建议，不是用户已有承诺。
- 主仓库的文件、分支、暂存区和原有变更应保持不变。用户主动 fetch 会更新对象/远程跟踪引用，这是明确例外，不等于切换或合并代码。
- 本轮已获推进授权：按prompt完成正式栈收敛、TASK-03至06和首个贯通检查点；用户明确选择DEC-14。旧有限验证保留证据，旧脚本保持参考用途。
- 后续已提出能力：REQ-010依赖变化查询与按按钮执行命令。第一版不执行安装/删除命令；用户自行运行后产生的依赖目录可以按DEC-09保留。
- 尚未纳入的其他能力：远程URL克隆、批量快照/补丁包、分支开发/提交/push、自动构建、云服务/账号、多仓库并行任务、自动更新客户端。
- 子模块、LFS、符号链接等特殊条目先做检测与明确提示；在支持能力验收前不能声称“完整导出成功”。具体处理见 P-04。
- 首批验证平台是用户本机Windows的实际版本/架构，由TASK-01复核记录；不强制承诺所有Windows10/11。其他设备发行后续再定义兼容矩阵（DEC-07）。
- 本轮允许更新正式工程、下载项目内便携.NET工具链、构建及隔离验证；不涉及真实远程fetch、全局工具安装、清理旧业务目录或执行依赖命令。产品未来fetch不等于本轮对真实远程的操作授权。
- 2026-11-20用户先要求清理非产品内容与历史，随后明确根README保留、测试只留本地，再要求工作文档暂时一并提交。当前纳管产品源码/构建配置/README及临时工作Markdown；测试、工具链/产物、原始JSON/原型及AI工具配置保持本机。之后按用户指令清理工作文档，未指定时间；历史规则保留日期但不覆盖最新修订。

日期内部规则建议为 `[开始日当地00:00, 结束日次日当地00:00)`；后端统一按日历日计算，不直接加86400秒。无效时区、无法唯一映射的边界明确失败并保留输入；配置恢复不得悄悄换时区。空日期不限时间，详情可看作者时间。

保留规则建议：每个输出位置维护精确相对路径及“保留/移除”选择；提供node_modules、用户选择的.env等快捷项，实际勾选由用户决定，随后记忆。没有选择的路径默认随旧内容移除，已缺失的保留路径提示但不凭空创建。不支持通配符；祖先/子项重复选择归一为互不重叠的根。任一保留根与上次导出或新版本的受跟踪文件相等/相含，预检阻止本次导出并要求取消对应保留项，不静默覆盖或合并。受跟踪环境文件同样受此规则约束。

## 4. 需求与验收

### REQ-001：选择与记住本地仓库

- 通过系统文件夹选择器选择仓库；支持普通仓库及可验证的 linked worktree 入口，获取实际根目录与 common directory。
- 记住最近仓库、完整引用名、日期条件、时区、输出目录及保留设置。重启时核验路径、引用、时区与目录身份；无效项保留记录并明确提示，不静默换值。
- 不把默认路径写死为旧 store-applet；配置不保存凭据或远程令牌。
- **AC-001**：选择两个不同仓库分别查询，重启后正确恢复最近一项；不存在、空仓库及非仓库路径得到不同提示，不执行导出。
- 状态：仓库选择是已确认目标的必要行为，配置记忆为便利性建议。

### REQ-002：手动更新远程引用

- 显示本机已有的本地/远程跟踪引用，保留完整 ref，支持非 origin 远程和分支名搜索。
- 仅用户点击“更新远程提交”时 fetch 选定远程；使用受控引用映射仅更新该远程的跟踪分支，显式禁止 prune、tags 自动跟随和子模块递归获取。不 pull、不 checkout，不自动获取所有远程；不依赖仓库默认 fetch 配置来保证这些行为。
- 失败、认证需求或取消显示具体状态，允许继续浏览本地历史；成功后可重新查询，但不静默切换当前选定提交 OID。
- **AC-002**：在本地测试远程产生新提交，手动 fetch 后可选中它；即使仓库配置了 prune、自定义本地分支映射或子模块递归，也只更新约定命名空间；认证/断网失败不影响旧导出，源分支与文件变更不变。
- 状态：手动更新已确认；具体引用及失败行为为设计建议。

### REQ-003：按日期和引用查询提交

- 采用 P-01/P-02；查询开始时把引用解析为完整提交 OID，确保本次列表不受后来 fetch 影响。
- 列表显示提交时间、时区、短 OID、摘要；详情能看到完整 OID、作者及作者时间。筛选零结果正常展示空状态。
- 分页/增量加载、选择行、已导出版本各有独立状态。新查询覆盖旧查询时，旧异步响应不能污染新结果。
- 2026-11-20用户追加：分页可直达首页/末页并输入页码跳转；日期提供日历入口且保留手输/清空，界面解释筛选与完整版本导出的区别。沿用P-01/P-02，不改变后端日期含义。
- 按P-10区分浅历史、不支持的部分克隆和普通仓库。浅仓库无结果提示“本机已知历史无匹配”，不能宣称远端无提交；不隐式加深历史。
- **AC-003**：起止边界、同日、无结果、时间倒序、作者/提交者时间不同、合并、无效/歧义时区均有唯一预期；连续翻页可到第三页；浅历史缺口可见，partial仓库不触发隐式联网。
- 状态：时间筛选已确认；具体规则按P-01/P-02和契约v1实现，完整AC核对留TASK-08。

### REQ-004：选择、预览和打开

- 点击提交仅预览，不立即改写输出；明确区分“已选择”和“上次导出”。用户可能已手动修改输出，不能把上次OID显示为当前目录全部内容仍严格匹配的保证。
- 显示摘要、变更文件列表和按需加载的文本 diff；合并提交预览明确标注“相对第一父提交”，根提交对比空树，二进制文件以类型/大小提示。
- 成功后提供“打开输出文件夹”和复制完整 OID；未成功时不显示完成标识。
- 首版比较上次成功导出与本次提交中声明/锁文件的对象变化（含新增/删除），发现变化或已知信息不足时提示“请自行同步依赖”，不解析并执行增删包命令；也不保证保留的node_modules已兼容。具体受识别文件清单由TASK-03锁定，首批为package.json、package-lock.json、npm-shrinkwrap.json、pnpm-lock.yaml、yarn.lock、pnpm-workspace.yaml（包含工作区子目录中的对应文件）。
- **AC-004**：选择B但未导出时仍显示上次A；失败不显示B成功；声明/锁文件变动、删除及首次导出得到准确提示，保留依赖不显示“已同步”；打开路径正确。
- 状态：选择提交已确认，预览/打开为便利性建议。

### REQ-005：完整导出指定提交

- 按 P-03/P-04 冻结提交和 tree OID；查询、预览与导出统一禁用 replacement objects，保证 OID 对应原始对象；导出整个树，不因日期范围而遗漏此提交之前已有的文件。
- 保留相对路径、隐藏文件、空文件、中文文件和二进制字节；Git 不跟踪的空目录无需凭空生成。
- 导出前检查目标文件系统是否能表示路径，包括大小写冲突、保留名、路径穿越和特殊模式；失败发生在替换之前。
- **AC-005**：在应用保留项前，新代码暂存树与Git树逐项比对一致；最终目录仅含这些跟踪文件与明确保留的本地内容。新增/修改/删除/重命名/隐藏/空/中文/二进制均正确；export-ignore不漏文件、export-subst不改字节；特殊或缺失对象明确失败。
- 状态：完整版本已确认；精确定义为 P-03/P-04。

### REQ-006：在固定目录完整替换

- 首次按P-09绑定新建/空专用目录；未知非空目录拒绝直接接管。旧code/code-junk不迁移。本机本地卷为首版范围。
- 只替换已登记且身份匹配的目录；按P-07迁移显式保留项，其余旧内容清除，包括新版已删除代码。保留项从本次开始时的目标取得，不来自源仓库脏文件。
- 每次导出前显示保留/移除清单与冲突；依赖声明和锁文件随版本更新。选择全部移除仍是可用模式，不能被新功能取消。
- 永久拒绝磁盘根、源仓库/所有关联工作区、Git 元数据、应用/配置目录及与上述目录存在包含关系的目标；拒绝目标/相关父路径的链接、junction 或身份异常。
- **AC-006**：A→B后旧源码独有文件消失；选保留的环境/依赖字节及内部结构仍在，未选的旧内容消失；package/lock与B一致。再次取消保留可移除它们；重复及父子保留选择规范化并展示；Git跟踪冲突、未知非空/危险路径在移动旧目录前拒绝；不自动安装依赖。
- 状态：固定目录替换已确认；路径和归属限制是实现保护方案。

### REQ-007：失败、取消与恢复
