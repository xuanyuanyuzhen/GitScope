## 3. 缺陷与设计影响

下列问题来自静态分析；除明确注明现场证据外，没有运行旧脚本重现。

| 编号 | 证据 | 缺陷 | 新设计需要保证 |
| --- | --- | --- | --- |
| LEG-01 | 45 | 无日期条件 | 时间字段、时区和起止边界必须可见、可验证 |
| LEG-02 | 228–231 | 翻页总是基于 `$pos`，没有保存浏览页码 | 浏览页码与实际打开的提交分开管理；可连续翻页 |
| LEG-03 | 221、225、237；95–97 | 先改 `$pos` 再 checkout，失败不回滚 | 验证磁盘 HEAD 后才更新“当前代码版本” |
| LEG-04 | 24、31–40、94、148 | 已有 WorkPath 未核验身份、归属及是否等于源目录 | 校验标准化路径、Git common directory、worktree 正反向登记、应用归属 |
| LEG-05 | 43–55、68–88、203–206 | 历史命令失败/空列表未独立处理 | 空仓库、无结果、命令失败分别反馈 |
| LEG-06 | 55、164–170 | 重启不恢复分支；提示“t 后 n 从最早开始”与实际不符 | 记住查询状态，恢复时重新核验；列表导航不偷偷切换代码 |
| LEG-07 | 117、138–142 | 过滤所有含 HEAD 的远程名，且处理写死 origin | 保存完整 ref、remote 类型及实际名称 |
| LEG-08 | 92–99、137–160 | 没有明确展示学习修改；Git 可保留部分不冲突修改 | 切换前检查暂存、未暂存和未跟踪内容；不静默携带修改 |
| LEG-09 | 9、33、148–154、216 | “主项目完全只读”与关联 worktree/共享分支行为不符 | 精确界定源工作区保护与 Git 共享元数据变更 |
| LEG-10 | 44–49 | 全量读取并反复数组追加 | 先验证真实规模；提供加载、取消状态，不虚构性能指标 |

保留 Git CLI、独立学习区、提交摘要/diff、分支检索和逐步浏览的思路；不直接将单体交互脚本包一层界面作为最终架构。
