# GitScope

Windows 桌面工具，用于查询本地 Git 提交历史，并把选中版本的完整代码导出到固定目录。更新输出时，可选择保留环境文件和已安装依赖。

## 功能

- 选择本地仓库和引用，按日期筛选提交，预览改动和文本差异。
- 每页 50 条记录，支持首页、末页和输入页码跳转；提供日历选择日期。
- 导出指定提交的完整 Git 文件内容，包括中文路径、空文件和二进制文件。
- 更新固定输出目录时，可保留 `.env`、`node_modules` 等精确路径；提供中断恢复入口。
- 支持浅色、夜间和跟随系统主题，记住仓库、查询和输出设置。

## 构建和启动

环境：Windows x64、Git、PowerShell。首次准备工具链需要联网。项目锁定 .NET SDK 10.0.404，下载到项目内 `.tools`，无需全局安装 SDK。

```powershell
git clone https://github.com/xuanyuanyuzhen/GitScope.git
cd GitScope
.\scripts\bootstrap.ps1
.\scripts\build.ps1 -Publish
.\Start-GitScope.cmd
```

`bootstrap.ps1` 会校验 SDK 下载文件的 SHA512。构建完成后，可双击根目录的 `Start-GitScope.cmd`；程序输出位于 `artifacts/app`。源码仓库不包含 SDK 或预编译程序。

重新构建只需运行 `scripts/build.ps1 -Publish`。发布前关闭正在运行的 GitScope，避免程序文件被占用。

## 使用方法

1. 选择本地 Git 仓库，读取并选择分支或引用。
2. 按需填写开始、结束日期和时区，点击“查询历史”，选中一条提交。
3. 绑定新建或空的专用输出目录，勾选需要保留的环境或依赖路径。
4. 点击右下角“检查更新计划”，核对目录和保留项，再点击最右侧“导出到此目录”。
5. 成功后打开目录；若启动时显示未完成的更新，先通过恢复入口处理。

**日期只筛选提交列表。** 起止日均包含，留空表示不限；实际导出始终是选中提交的完整代码。手动输入日期或点击“日历”均可；日历支持月份跳转、今天和清空。

**更新会移除未选择保留的旧内容。** 包括旧源码、本地修改和新增文件。保留项使用精确相对路径，不支持通配符，也不能与新旧版本的受跟踪文件重叠。`package.json` 和锁文件随选中版本更新，应用只提示依赖变化，不自动安装或删除依赖。

## 当前范围

- 只读取本机已有 Git 对象；手动远程更新功能尚未提供。不会切换源仓库分支或把源目录未提交内容带入导出。
- 输出目录目前仅支持本机固定 NTFS 磁盘；拒绝危险路径、目录重叠和链接祖先。
- 遇到子模块、符号链接、LFS 指针或 Windows 无法表示的文件路径时，会停止导出并说明原因。
- 替换期间请停止输出目录内的开发服务器、安装器等写入进程；应用不提供任意外部并发写入的快照保证。

配置和恢复记录默认保存在 `%LOCALAPPDATA%\GitScope`，不放进代码输出目录。可使用 `--state <目录>` 指定独立配置位置，使用 `--repo <仓库路径>`指定启动仓库；这些参数不会自动执行导出。

## 仓库结构

| 路径 | 内容 |
| --- | --- |
| `src/GitScope.App` | 桌面界面、配置和应用入口 |
| `src/GitScope.Core` | Git 查询、完整导出、保留规则和恢复事务 |
| `scripts` | 工具链准备和构建脚本 |
| 根目录配置文件 | SDK 版本、编译设置、还原配置和启动入口 |
